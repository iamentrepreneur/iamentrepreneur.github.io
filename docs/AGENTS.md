# AGENTS.md — правила для Codex

Ты работаешь над персональным портфолио Ильи Волкова, размещаемым на GitHub Pages. Перед изменениями прочитай `PROJECT_CONTEXT.md`, `DESIGN.md`, `ARCHITECTURE.md`, `CONTENT.md` и `README.md`.

## Обязательные правила
1. Соблюдай утвержденную дизайн-систему. Не заменяй ее своим «современным» шаблоном. Никаких эмодзи, случайных иллюстраций, градиентов, glassmorphism и лишних анимаций.
2. Держи архитектуру максимально простой: Astro + Tailwind, статический сайт. Не добавляй backend, CMS, базы данных, API, глобальные state managers или UI kits без конкретной необходимости.
3. Реализуй обе темы: Light по умолчанию, Dark по выбору, хранение в localStorage, без flash неправильной темы.
4. Реализуй RU и EN с корректными маршрутами и переключением на соответствующую страницу.
5. Проекты показывай в заданном порядке: DogSpace, Coffee Platform, Relayo; затем HH Radar и Bitrix Partner CRM.
6. Все репозитории пет-проектов приватные. Не раскрывай код, приватные ссылки, конфиденциальные сведения и секреты.
7. Не выдумывай достижения, архитектурные детали, статусы реализации и цифры. Если данных недостаточно — оставь явный TODO и спроси владельца.
8. Пиши семантическую, доступную разметку, адаптивную верстку, чистый CSS. Не дублируй контент и компоненты без причины.
9. Не проводи рефакторинг ради рефакторинга и не создавай лишних абстракций.
10. Не публикуй сайт и не создавай публичный репозиторий без отдельного подтверждения владельца.

## Процесс
- Перед каждой задачей кратко опиши план и затрагиваемые файлы.
- Делай небольшие логически завершенные изменения; не смешивай независимые задачи.
- После изменений запускай доступные проверки (`npm run build`, тесты/линтеры при наличии).
- Если проверка не выполнялась, честно сообщи об этом.
- Коммиты предлагай на английском языке; не коммить без просьбы пользователя.
- Пояснения и документацию веди на русском, имена переменных, компонентов, технические идентификаторы — на английском.

## Definition of Done для MVP
- Все 5 проектов видны на главной, каждый имеет RU/EN case study.
- Обе темы работают и доступны с клавиатуры.
- Адаптивность от 320px, без горизонтального скролла.
- Корректные SEO meta, заголовки, ссылки, локализация.
- Успешная production-сборка для GitHub Pages.
- Никаких фальшивых сведений, изображений или внешних сервисов.
